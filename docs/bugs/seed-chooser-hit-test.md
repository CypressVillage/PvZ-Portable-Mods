# 选卡界面第二页植物不可见与出战栏跨页植物不可退回 Bug 总结

## 1. Bug 现象描述
在完善植物分页系统后，暴露了以下两个与植物状态及页面切换相关的交互问题：
1. **第二页植物隐身但可点：** 切换到第二页时，发现新增的 Mod 植物卡片并没有被渲染出来，但是该位置是可点击的，点击后植物会被放置到上方的出战栏并正确显示。
2. **出战栏植物跨页不可退回：** 如果某植物已经被选中进入了上方的出战栏，此时如果玩家翻页到一个不包含该植物的页面（比如翻到第二页，而出战栏中有豌豆射手），再去点击出战栏中的这个植物，无法将其退回卡池。

## 2. 崩溃与错位原因分析

### 2.1 第二页植物不渲染原因
在 `SeedChooserScreen::Draw` 方法遍历所有植物卡片进行绘制时，我们为了只渲染当前页面的植物，加入了一个拦截条件：
```cpp
else if (i >= pageStart && i < pageEnd && pageEnd <= maxPlants)
```
其中 `pageEnd <= maxPlants` 是一个**逻辑漏洞**。
假设总植物数量 `maxPlants` 为 50 个。
在第一页时，`pageEnd` 为 40（或 48），此时 `40 <= 50` 为 `true`，植物正常渲染。
而在第二页时，`pageStart` 为 49，`pageEnd` 会变为 49 + 40 = 89。由于第二页的理论容量上限（89）大于当前的植物总数（50），`pageEnd <= maxPlants` 这一条件永远为 `false`，导致第二页的任何植物都被无情 `continue` 拦截掉，没有触发 `DrawSeedPacket` 的绘制调用。

### 2.2 出战栏植物跨页不可退回原因
玩家点击出战栏时，调用的碰撞检测是 `SeedChooserScreen::SeedHitTest(int x, int y)`。
这个函数的逻辑起初被修改为：**只在当前页面的植物索引范围内（`startIdx` 到 `endIdx`）循环测试碰撞。**
对于放在出战栏的植物，其状态是 `SEED_IN_BANK`，它的坐标也的确被更新到了屏幕上方出战栏的位置。
但由于循环范围被死死卡在了当前页面的索引内，导致不在当前页的植物哪怕实际上就在玩家鼠标点击的正下方，也因为根本没参与这轮循环而被判定为未击中（命中返回 `SEED_NONE`）。从而无法执行将其退回的逻辑。

## 3. 修复方案

针对以上问题，分别对渲染和点击检测逻辑进行了修复：

1. **修正第二页的植物渲染条件：**
   将渲染拦截条件中引发逻辑短路的 `pageEnd <= maxPlants` 移除。只要植物索引在该页的区间内即可：
   ```cpp
   else if (i >= pageStart && i < pageEnd)
   {
       GetSeedPositionInChooser(i, aPosX, aPosY);
   }
   ```
   因为循环本身是 `for (int i = 0; i < maxPlants; i++)`，`i` 永远不会超过 `maxPlants`，所以只需要确保 `i < pageEnd` 即可完美过滤该页面的植物。

2. **修正跨页出战栏植物的碰撞检测：**
   将 `SeedHitTest` 的循环范围改回遍历全部植物 (`for (int i = 0; i < maxPlants; i++)`)，但增加过滤条件：如果植物不在出战栏中（即在卡池中待选）**且**它不在当前页面，则忽略它的碰撞。
   ```cpp
   for (int i = 0; i < maxPlants; i++)
   {
       // ... 省略常规校验 ...
       // 如果植物在选卡池里，而且它不属于当前这一页，则不参与点击检测
       if (aChosenSeed.mSeedState == SEED_IN_CHOOSER && (i < startIdx || i >= endIdx)) 
           continue;

       if (Rect(aChosenSeed.mX, aChosenSeed.mY, SEED_PACKET_WIDTH, SEED_PACKET_HEIGHT).Contains(x, y)) 
           return aSeedType;
   }
   ```
   这样一来，处于出战栏中 (`SEED_IN_BANK`) 的植物不受当前页面索引的限制，只要玩家鼠标点中，就会稳定触发命中并被退回；而卡池里的植物依然遵循严格的本页检测，防止玩家点到重叠在同一坐标的其他页面植物。

## 4. 总结
翻页系统不仅带来了**界面渲染（空间）**的层级切分，同时也要考虑到**对象状态（逻辑）**带来的特例。
对于分页系统来说：
- UI元素的可见性应该严格受限于当前所处的页码。
- 但对于那些脱离了列表本身（被选中、置顶或者悬浮）的元素，其检测和交互往往具有全局优先级，不应再受到底层页面列表的限制。
